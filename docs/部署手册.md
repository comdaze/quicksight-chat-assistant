# QuickSight 分析助手 · 部署手册

面向在客户 AWS 账号中部署本方案的管理员。按章节顺序操作，大约需要 1～2 小时（不含审批）。

## 1. 方案概述

在任意 QuickSight 分析或仪表盘里嵌入一个聊天窗口。用户在 QuickSight 里直接提问，助手会：

- 按当前控件筛选查询分析背后的数据，在聊天窗口里画图（ECharts）并给出结论；
- 告诉用户要在上方控件里选什么值（聊天窗口无法替用户改控件）；
- 预览“把某个图表改成柱状图/折线图”，用户点“应用到分析”后才真正修改分析，可撤销；
- 可选：调用企业已有的 MCP 服务（如 DataHub、Metabase），查询指标口径或数据。

```
QuickSight 分析 / 仪表盘
  └ 自定义可视内容（iframe）：聊天页
       │ HTTPS，Identity Center 登录后的会话令牌
       ▼
API Gateway HTTP API ─▶ Web Lambda ──────────────▶ DynamoDB（任务、登录状态、待确认修改）
                           │ 提交任务（立即返回）        ▲ 心跳 / 结果
                           ▼                            │
                    AgentCore Runtime（Strands Agent，每个会话一个 microVM）
                           │ MCP + SigV4
                           ▼
                    AgentCore Gateway
                      ├ analysis 工具 Lambda ─▶ QuickSight API（读分析、改分析、查权限）、S3（修改前备份）
                      ├ data 工具 Lambda（VPC）─▶ 数据集背后的数据库（只读 SQL）
                      └ 企业 MCP（可选）
模型：客户自己的 OpenAI 兼容端点（地址和 API Key 保存在 Secrets Manager）
```

所有资源部署在 QuickSight 所在区域（中国区为北京 cn-north-1），由一个 CDK 栈管理。

## 2. 前提条件

| 项目 | 要求 |
|---|---|
| AWS 账号与区域 | QuickSight 所在区域（北京 cn-north-1 已验证）。部署账号需要管理员级权限（创建 IAM 角色、VPC 端点等） |
| QuickSight | Enterprise 版，用户通过 IAM Identity Center 登录；要接入的分析已存在 |
| IAM Identity Center | 已启用，且 QuickSight 用户的邮箱与 Identity Center 用户邮箱一致 |
| 模型 | 一个 OpenAI 兼容的 Chat Completions 端点（支持 tools / function calling 和流式输出），建议 HTTPS |
| 部署机器 | macOS 或 Linux；Node.js 20 及以上；Python 3.9 及以上并已安装 `pip`、`boto3`；能访问 npm 与 PyPI（可用企业镜像：`npm config set registry …`、`PIP_INDEX_URL`） |
| CDK 引导 | 目标账号与区域执行过一次 `npx cdk bootstrap aws://<账号>/cn-north-1`（在 `infra/` 目录下执行） |

> 构建时会下载 Linux arm64 的 Python 包（`pip --platform`），部署机器不需要 Docker。

## 3. 填写 config.json

```bash
cp config.example.json config.json
```

| 字段 | 说明 |
|---|---|
| `prefix` | 资源名前缀，2～12 位小写字母或数字，如 `qsca`。同一账号部署多套时用不同前缀 |
| `region` | QuickSight 所在区域，如 `cn-north-1` |
| `quickSight.namespace` | QuickSight 命名空间，通常是 `default` |
| `quickSight.allowedAnalysisIds` | 允许接入聊天的分析 ID 列表；`["*"]` 表示全部（仍按用户权限控制） |
| `identityCenter.samlEntityId` | Identity Center 应用的“SAML 受众”，自定义一个 URN，如 `urn:quicksight-chat-assistant:chat` |
| `dataAccess.vpc` | 数据工具 Lambda 所在网络。数据库在 VPC 内时填写 `vpcId`、`subnetIds`；数据库可公网访问时设为 `null` |
| `dataAccess.vpc.securityGroupIds` | 额外挂到数据工具 Lambda 上的安全组（例如数据库已放行的安全组）；可留空，见 5.4 |
| `dataAccess.vpc.createInterfaceEndpoints` | `true`：在该 VPC 创建 QuickSight 与 Secrets Manager 接口端点（子网没有 NAT 时必需）。VPC 里已有这两个端点时设为 `false` |
| `dataAccess.datasourceSecretPrefix` | 数据库凭证的密钥名前缀，默认 `quicksight-chat-assistant/datasource/`，见 5.3 |
| `dataAccess.extraSecretArns` | 若 QuickSight 数据源本身使用 Secrets Manager 凭证，把这些密钥 ARN 列在这里以授权读取 |
| `mcpTargets` | 企业 MCP 服务，见第 6 节；没有就留空数组 |
| `runtime.idleSeconds` | 会话空闲多久后回收 microVM，默认 300 秒 |
| `runtime.maxLifetimeSeconds` | 单个会话最长存活时间，默认 28800 秒（8 小时），也是单个分析任务的时长上限 |
| `api.rateLimit` / `api.burstLimit` | API 限流（每秒请求数 / 突发） |
| `frameAncestors` | 允许嵌入聊天页的来源，中国区保持默认即可 |

## 4. 部署

```bash
./qsca --profile <你的 AWS CLI profile> deploy
```

命令会依次：构建 4 个程序包到 `build/` → 安装 CDK 依赖 → `cdk deploy`。涉及 IAM 变更时，CDK 会列出变更并请你确认（加 `--yes` 跳过确认）。首次部署约 10 分钟，结束时打印输出：

| 输出 | 用途 |
|---|---|
| `ChatUrl` | 聊天页地址（接入分析时使用） |
| `AcsUrl` | 填到 Identity Center 应用的“应用程序 ACS URL” |
| `SamlEntityId` | 填到 Identity Center 应用的“应用程序 SAML 受众” |
| `ModelSecretName` | 模型配置密钥名，见 5.2 |
| `IdpMetadataParameter` | Identity Center 元数据保存位置，见 5.1 |

随时可用 `./qsca --profile <p> outputs` 再次查看。

## 5. 部署后配置

### 5.1 IAM Identity Center 应用（必需，控制台手工操作）

Identity Center 的自定义 SAML 应用无法通过 API 创建，请在控制台操作：

1. 打开 IAM Identity Center 控制台 → **应用程序** → **添加应用程序** → **我有要设置的应用程序** → **SAML 2.0** → 下一步。
2. 显示名称填“QuickSight 分析助手”。
3. **IAM Identity Center 元数据**：点 **下载**，保存 XML 文件（下一步要用）。
4. **应用程序属性**：
   - 应用程序 ACS URL：部署输出的 `AcsUrl`
   - 应用程序 SAML 受众：部署输出的 `SamlEntityId`
5. 提交后，进入应用 → **操作** → **编辑属性映射**：
   - `Subject` 映射到 `${user:email}`，格式选 `emailAddress`
6. **分配用户和组**：把需要使用助手的 QuickSight 用户或组分配给这个应用（未分配的用户无法登录）。
7. 上传元数据：

```bash
./qsca --profile <p> idp-metadata ~/Downloads/<下载的元数据>.xml
```

约 5 分钟内生效，不需要重新部署。

> 用户的 Identity Center 邮箱必须与其 QuickSight 用户邮箱一致，助手按邮箱查找 QuickSight 用户和权限。

### 5.2 模型（必需）

在 Secrets Manager 控制台找到密钥 `<prefix>/model-config`（部署输出 `ModelSecretName`）→ **检索密钥值** → **编辑** → 选择“纯文本”，填入：

```json
{
  "base_url": "https://你的模型端点/v1",
  "model": "模型名称",
  "api_key": "你的 API Key",
  "temperature": 0.2,
  "timeout": 120
}
```

| 字段 | 说明 |
|---|---|
| `base_url` | OpenAI 兼容端点，到 `/v1` 为止（助手会请求 `<base_url>/chat/completions`） |
| `model` | 模型名称，需支持工具调用（function calling） |
| `api_key` | API Key；端点不需要时可填任意非空字符串 |
| `temperature` | 可选，建议 0～0.3 |
| `timeout` | 可选，单次模型请求超时秒数 |

保存后最迟 60 秒生效，切换模型也只需改这个密钥。也可以用命令（API Key 不回显）：`./qsca --profile <p> model`。

> 提问内容、查询结果会发送到这个模型端点，请确认端点符合企业的数据合规要求，并使用 HTTPS。

### 5.3 数据源凭证（使用内置数据查询时必需）

QuickSight 不会提供它保存的数据库密码，所以需要为分析用到的每个 **QuickSight 数据源** 单独保存一个 **只读** 数据库账号：

- 密钥名：`quicksight-chat-assistant/datasource/<DataSourceId>`（前缀可在 `config.json` 修改）
- 密钥值：`{"username": "只读用户", "password": "密码"}`
- 必须与部署在同一区域

`./qsca --profile <p> check --analysis <分析ID>` 会列出分析用到的每个数据源和对应的密钥名。也可以用命令创建：

```bash
./qsca --profile <p> datasource-secret <DataSourceId>
```

建议在数据库里为助手单独创建只读账号（只授予相关表的 `SELECT`）。助手的每次查询还会在会话级设置只读事务和 20 秒语句超时。

### 5.4 网络（数据库在 VPC 内时）

- 数据工具 Lambda 部署在 `dataAccess.vpc` 指定的子网，并带一个新建的安全组（出站全放行）。
- **数据库安全组必须放行这个 Lambda**：放行 `<prefix>-chat-assistant-DataToolsSg…` 安全组，或放行子网网段，或在 `securityGroupIds` 里挂一个数据库已放行的安全组。
- 推荐使用 QuickSight VPC 连接所在的 VPC 和子网：既然 QuickSight 能连上数据库，这些子网通常也能连上。
- 子网没有 NAT 时，保持 `createInterfaceEndpoints: true`，Lambda 通过接口端点访问 QuickSight 与 Secrets Manager。
- 数据库在另一个区域、通过对等连接访问时，同样适用（已在“北京 QuickSight → 宁夏 Aurora”的对等连接下验证）。

### 5.5 接入分析

```bash
./qsca --profile <p> attach <分析ID>            # 只打印聊天窗口地址，不修改分析
./qsca --profile <p> attach <分析ID> --apply    # 把聊天窗口加到分析的第一个工作表
```

- 接入脚本会读取分析的全部参数，生成形如 `…/?analysis=<ID>&p.<参数>=<<$参数>>…` 的地址，聊天窗口据此知道“当前控件值”。
- `--sheet <工作表ID>` 指定工作表；`--replace <visual_id>` 用聊天窗口替换某个已有图表并保留其位置。
- 不想用脚本时：在分析里 **添加** → **自定义可视内容（Custom visual content）**，URL 填 `attach` 打印的地址。
- 分析新增或删除参数后，重新运行一次 `attach --apply`，更新地址。
- 修改后在 QuickSight 里 **发布** 仪表盘，仪表盘里才会出现聊天窗口。
- 可选：在分析中创建一个参数 `pViewer`，默认值使用“动态默认值”映射为当前用户邮箱。聊天窗口会据此发现浏览器里切换了 QuickSight 用户，并清除上一个用户的聊天记录。它不用于授权。

### 5.6 自检

```bash
./qsca --profile <p> check --analysis <分析ID>
```

逐项检查模型、Identity Center 元数据、分析是否已接入、每个数据源的凭证是否存在。全部为 ✓ 后，请一位用户在 QuickSight 里打开分析，点聊天窗口里的“使用 Identity Center 登录”，问一个问题。

管理员还可以不经浏览器做一次端到端测试（会读取会话签名密钥，仅限管理员使用）：

```bash
./qsca --profile <p> smoke --analysis <分析ID> --email <有权限用户的邮箱>
python3 tests/e2e.py --profile <p> --analysis <分析ID> --editor <可编辑分析的用户邮箱> \
  --visual <某个折线图或柱状图的 visual_id> --dataset <数据集ID> --control-column <控件取值的列>
```

## 6. 接入企业 MCP 服务（可选）

在 `config.json` 的 `mcpTargets` 中添加，重新执行 `./qsca deploy`。助手会把这些工具与内置工具一起交给模型。

```json
"mcpTargets": [
  {"name": "datahub", "endpoint": "https://mcphub.example.com/datahub/mcp", "description": "指标口径与血缘",
   "auth": {"type": "oauth", "providerArn": "arn:aws-cn:bedrock-agentcore:cn-north-1:<账号>:token-vault/default/oauth2credentialprovider/datahub", "scopes": ["read"]}},
  {"name": "metabase", "endpoint": "https://mcphub.example.com/metabase/mcp",
   "auth": {"type": "apiKey", "providerArn": "arn:aws-cn:bedrock-agentcore:cn-north-1:<账号>:token-vault/default/apikeycredentialprovider/metabase", "parameterName": "X-API-Key"}}
]
```

| 字段 | 说明 |
|---|---|
| `name` | 目标名，工具在模型中显示为 `<name>___<工具名>`；`analysis`、`data` 为保留名 |
| `endpoint` | MCP 服务的 **公网 HTTPS** Streamable HTTP 地址（中国区 Gateway 不能访问 VPC 内地址） |
| `auth.type` | `none`：不认证；`oauth` / `apiKey`：先在 AgentCore Identity 创建凭证提供方，再填 `providerArn`；`iam`：SigV4（MCP 服务托管在 AgentCore Runtime 上时，填 `service: "bedrock-agentcore"`、`runtimeArn`，跨区域时加 `region`） |

注意：

- 中国区 Gateway 只支持 MCP 协议版本 `2025-03-26`，企业 MCP 服务需要兼容这个版本。
- 企业 MCP 工具 **不会** 收到用户身份。它们看到的是服务账号权限，请只开放只读工具（在 MCPHub 侧做工具白名单）。
- 工具较多时会占用模型上下文，建议每个目标只暴露必要工具。

## 7. 权限与安全

| 主题 | 机制 |
|---|---|
| 谁能登录 | 只有分配到 Identity Center 应用的用户；SAML 断言校验签名、受众、ACS、有效期、防重放 |
| 会话令牌 | HMAC 签名，8 小时有效，保存在聊天 iframe 的浏览器存储中 |
| 谁能查看数据 | 用户必须能在 QuickSight 中查看该分析或其发布的仪表盘；只能查询该分析用到的数据集 |
| 数据集安全 | 启用了 **行级权限（RLS）**、带 **数据集过滤条件** 或 **联接** 的数据集，内置查询直接拒绝（直接查数据库会绕过它们）；**列级权限** 限制的列对无权用户隐藏 |
| 查询安全 | 模型不写 SQL：只提交结构化的聚合请求，列名必须属于数据集、聚合与运算符来自白名单、取值全部参数化；只读事务、20 秒超时、最多 500 行 |
| 谁能修改分析 | 用户必须对该分析拥有 `quicksight:UpdateAnalysis`（与 QuickSight 共享设置一致）；模型只能生成预览，**应用** 只能由发起人在 10 分钟内点击按钮触发、只能一次；每次修改前把原定义备份到 S3（`<栈>-backups…/analysis-backups/`），可撤销 |
| 身份如何传到工具 | Runtime 在代码里把已验证的用户令牌附加到本方案自己的工具调用上，模型看不到也无法伪造；企业 MCP 工具收不到令牌 |
| 数据去向 | 提问和查询结果会发送到你配置的模型端点；日志写入 CloudWatch（不记录令牌和数据库密码） |
| 网络 | 聊天页通过 API Gateway 公网 HTTPS 访问，带限流；数据库只从数据工具 Lambda 访问 |

> 注意：SPICE 数据集上，内置查询读取的是数据库当前数据，可能比仪表盘的 SPICE 数据新；助手在回答里会注明。

## 8. 更新、回滚与卸载

- **更新**：拉取新版本代码后执行 `./qsca --profile <p> deploy`。模型密钥、Identity Center 元数据、数据源凭证不会被覆盖。
- **回滚**：使用上一个版本的代码目录再次执行 `deploy`。
- **卸载**：在 `infra/` 下执行 `AWS_PROFILE=<p> npx cdk destroy --context config=../config.json`。以下资源会保留，需要手动删除：S3 备份桶（含分析修改备份）、SSM 参数 `/<prefix>/idp-metadata`、`quicksight-chat-assistant/datasource/*` 数据源密钥、分析中的聊天可视对象、Identity Center 应用。

## 9. 费用构成

按用量计费，没有常驻计算。主要费用：AgentCore Runtime（会话活跃的 CPU 和内存时长）、AgentCore Gateway 调用、Lambda、API Gateway、DynamoDB 按需、Secrets Manager 密钥（每个每月计费）、**VPC 接口端点（2 个端点 × 子网数，按小时计费，通常是固定费用里最大的一项）**、CloudWatch 日志，以及模型端点费用。具体价格请以 AWS 中国区官网价格计算器为准。

## 10. 故障排查

| 现象 | 原因与处理 |
|---|---|
| 登录弹窗显示“尚未配置登录” | 未上传 Identity Center 元数据：`./qsca idp-metadata` |
| 登录后报 “audience mismatch” / “bearer confirmation does not match” | Identity Center 应用的 SAML 受众或 ACS URL 与部署输出不一致 |
| 登录弹窗进入 Identity Center 后报错 | 用户未分配到应用，或属性映射 Subject 未设为 `${user:email}` |
| 回答“管理员尚未配置模型” | 模型密钥仍是占位内容，见 5.2 |
| 回答“缺少已登录用户的身份” / “没有查看这个分析的权限” | 用户在 QuickSight 中没有该分析或仪表盘的权限，或邮箱不一致 |
| 回答“找不到数据源…的数据库凭证” | 按 5.3 创建密钥 |
| 回答“内置查询不支持这个数据集：…” | 数据集有 RLS、过滤条件、联接，或数据源类型暂不支持；可接入企业 MCP |
| 查询超时或连接失败 | 数据库安全组未放行数据工具 Lambda，或子网到数据库不通，见 5.4 |
| 聊天窗口提示“没有绑定分析” | 嵌入地址缺少 `analysis=`：重新执行 `attach --apply` |
| 应用修改后看不到变化 | 编辑器不会自动刷新，请手动刷新页面；仪表盘需要重新发布 |

日志位置：CloudWatch 日志组 `/aws/lambda/<prefix>-web`、`/aws/lambda/<prefix>-analysis-tools`、`/aws/lambda/<prefix>-data-tools`，以及 `/aws/bedrock-agentcore/runtimes/<prefix>_agent-…-DEFAULT`（每个会话一个日志流）。

## 11. 当前版本的限制

- 内置数据查询支持 PostgreSQL、Aurora PostgreSQL、MySQL、Aurora MySQL、MariaDB、RDS（PostgreSQL / MySQL）数据源，数据集需为单表或自定义 SQL；Athena、Redshift、S3 等暂不支持（可通过企业 MCP 补充）。
- 图表修改只支持折线图与柱状图互换。
- 聊天窗口不能直接修改控件，只能提示用户选择的值（QuickSight 的 iframe 沙箱限制）。
- 修改分析后编辑器不会自动刷新；若用户在编辑器中有未保存的修改，与助手的修改可能互相覆盖。
- 取消任务时，如果模型正在“思考”，要等这一轮结束才会停止（通常几秒到几十秒）。
